# 架构与协议边界

## Harness bundle

`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`。Patch 通过包名挂载服务端入口；`dsh.client` 与 `./client` 导出提供设置页。运行时与宿主共享的包同时声明为 peerDependency 和开发依赖，独立第三方库位于 dependencies。

服务端注册 `chatgpt-subscription` provider、授权 flow 与 `chatgptProvider` Remote 服务。客户端先挂载 Remote 描述符，再通过注入作用域取得 API。前端只接收连接状态、脱敏账号、模型目录及精简用量，不接收凭据。

带参数的 Remote 在客户端挂载时必须提供 strict 输入 codec；`reconnect` 的参数解析器由前后端共享，只接受单个布尔字段 `confirmed`。客户端挂载测试使用真实 Gateway 检查发布 bundle 的描述符，宿主方法再次校验传入值。

## 两条连接路径

| 路径 | 授权 | 模型与推理 |
| --- | --- | --- |
| SIWC | 本插件的动态客户端注册、PKCE / OIDC、共享权限 | 公开 Models / Responses API |
| Codex 兼容 | 本插件自己的 Codex OAuth，实验性 | Codex 模型目录与 Responses backend-api |

两个路径不混用客户端、凭据或模型目录。一次只有一个活动连接。官方路径没有 API key 备用计费，也不会自动切换到 Codex。插件不读取其他客户端的缓存。

## 账号与凭据

`Store` 使用宿主 credentials 服务原子更新带 schemaVersion 的记录。状态、授权尝试、身份与凭据代次一起验证，以处理退出、切换账号和刷新竞争。未知记录版本不被覆盖；令牌不进入配置、前端、日志或安装包。

手动验证使用独立 DSH_HOME。profile 只隔离配置，不能证明凭据隔离。

## 推理与回放

适配器按账号和凭据代次缓存模型目录。请求通过当前模型声明的能力构建。工具保留命名空间及 call_id；流只有在收到 `response.completed` 后才报告成功。失败、断流、取消与 incomplete 分开处理。

等待响应头与流中相邻事件的超时分别由插件配置 `responseTimeoutMs`、`idleTimeoutMs` 控制，默认均为 120000 毫秒，允许 1000–600000 的整数。每个响应事件重置空闲计时；到期会中止该次尝试，分别记录 `timeout.headers` 或 `timeout.stream`，是否重试由恢复策略单独决定。

恢复由插件统一管理一个逻辑请求；SDK 与宿主的重试保持关闭。尚未向宿主输出任何内容块时，明确的连接故障、读取断流、超时、HTTP 408／500／502／503／504 和明确识别出的临时限流可以重试；已输出文字、推理或工具调用后停止自动恢复。协议错误、incomplete、登录／权限错误、额度耗尽、上下文或参数错误不重试。每次尝试创建独立客户端、流与计时器，并重新验证原身份的凭据；请求正文保持一致，已完成工具不会重新执行。

`recovery` 配置默认 `maxRetries: 2`、`initialDelayMs: 1000`、`maxDelayMs: 30000`、`jitterRatio: 0.2`。重试次数为 0–3 的整数，0 关闭恢复；延迟为 1–600000 毫秒的整数且初始值不超过上限，随机比例为 0–1。指数退避加入对称随机变化；有效 `Retry-After` 优先，超过等待上限时终止恢复。一次逻辑请求固定使用开始时的配置，最终错误保留原分类并附加已重试次数。取消、账号切换、重连和卸载会停止请求及恢复等待；没有收到内容不代表服务端没有处理，重试可能额外消耗订阅用量。

Remote `reconnect({ confirmed })` 在存在在途请求且尚未确认时返回 `confirmation_required` 和数量，不更改状态；等待重试的逻辑请求及模型／用量读取也计入数量。设置页使用原生模态对话框警告可能影响其他聊天，默认聚焦取消。确认后，或空闲时直接调用，返回 `reconnected`，更换本插件的网络请求代次，中止旧请求并清理缓存及在途读取。旧结果不得回填，也不能删除新代次的在途目录读取。被重置的请求返回 `CONNECTION_RESET`，不会自动补发。登录凭据、会话和工具结果不变，不操作全局网络池或其他插件。

上游错误与本地响应校验分开报告。已知错误优先按 code、再按 type 映射；未识别的 HTTP 错误保留状态码并使用对应 HTTP 分类或 `HTTP_ERROR`，没有 HTTP 状态的流内错误使用 `UPSTREAM_ERROR`。本地流校验仍使用 `PROTOCOL`，同时把固定诊断原因写入错误消息和安全诊断对象，使宿主保存会话时保留失败类别。诊断只使用预定义的事件、项目、文本、工具、推理、结束、用量或大小限制类别，不复制上游错误正文、未知错误码、工具参数或令牌。

回放绑定注册身份、模型、assistant phase 与 opaque reasoning 状态。同一身份下切换模型时，先校验历史内容，再投影为普通 assistant 消息和工具调用／结果；保留 phase、拒绝回答、工具名、参数和 call_id，移除旧模型的全部原生 reasoning（包括加密内容和可见推理摘要）。混合模型历史按每条消息的原模型分别处理，匹配当前模型的有效原生状态仍可回放。转换仅影响本轮请求，不改写已保存的会话；被编辑或裁剪的内容不会自动恢复。

身份不一致仍会阻止回放，单独返回 `REPLAY_IDENTITY_MISMATCH`，提示恢复原连接身份或在新会话中补充文字上下文。未知版本、无效元数据、内容校验失败和不完整工具调用继续返回 `REPLAY_INVALID`；切换模型不会绕过这些检查。

## 用量

Codex 用量接口映射为当前限额窗口、使用比例和重置时间。客户端展示剩余比例，数据缺失时不估算，更新失败时保留数据时间。模型可用状态与余额不能代替按日期／模型统计的历史 Token 明细。

0.2.21 将此前的「Business 登录」入口开放为「订阅登录（含余量）」，覆盖 Plus / Pro / Business。余量查询跟随 [上游 Codex 账号客户端](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client/rate_limit_resets.rs)，使用 `https://chatgpt.com/backend-api/wham/usage`，而不是推理 base 下的 `/codex/usage`。SIWC 没有已验证的百分比查询路径，遵循 [官方用量指引](https://developers.openai.com/siwc/ui-ux-guidelines)保留 ChatGPT 用量入口；用户明确确认并重新授权后才切换到余量连接。测试用合成 Plus / Pro / Team 响应验证路由、凭据隔离、缓存及页面切换，不代表真实 Plus / Pro 账号已验收。

账号数据读取等待授权流程完成后开始，避免凭据已写入、旧请求信号尚未切换的中间状态。首次用量读取失败会自动重试一次；取消、退出或切换连接时停止旧连接的重试。用量、模型和聊天请求的错误由各自调用方显示，不写入授权状态的全局错误。连接状态轮询失败的提示在下一次读取成功后清除。

可选余量入口通过公开 `sidebar.footer.action` 插槽挂载在主侧边栏底部，常驻仅展示 5 小时余量。点击使用浏览器原生 Popover 顶层展示详情，避开侧边栏裁剪；窗口变化时重排，窄窗口向上翻转并限制在视口内，支持外部点击、Escape 及键盘焦点恢复。每周比例、重置时间、刷新与订阅设置入口只在弹出卡片中展示。

订阅设置入口先关闭 Popover，再通过公开插槽注册表取得当前生效的 `sidebar.settings` 共享 store，调用 `openSection('chatgpt-subscription')`。每次点击重新解析，避免宿主重载后引用旧窗口实例；不操作页面 DOM 或新开浏览器。目标窗口不可用时在卡片内显示可重试提示。

`showSidebarQuota` 默认为 false，通过宿主 `configForms` 保存，账号与用量只留在内存。设置页与入口共用连接状态、用量缓存和在途读取；入口可见时约每分钟刷新用量，后台页面暂停轮询。最后一个读取者退出或插件卸载时清理定时器、监听器并丢弃迟到响应，不取消其他界面发起的登录。收起侧边栏、关闭开关或切换连接时关闭详情卡片。

## 已验证范围

自动化测试覆盖 OAuth、OIDC、loopback、刷新竞争、协议流、工具调用、回放、取消、脱敏及公开宿主服务。Business/Codex 路径另有真实文本和工具回合验证；Plus/Pro 真实推理、完整跨进程重登和非目标宿主版本行为尚未验收。手动结果不扩大 `engines.dsh` 声明。
