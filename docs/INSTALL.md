# 安装与使用

## 支持范围

插件以 Harness 独立 bundle 分发，包名与 provider ID 分别为 `dsh-chatgpt-pass`、`chatgpt-subscription`。支持的宿主版本为 **0.2.1-rc.5**、**0.2.2-rc.1** 和 **0.2.2-rc.3**；安装和启动时由 `engines.dsh` 检查兼容性。使用 rc.3 时需要插件 **0.2.20** 或后续明确支持该宿主的版本；0.2.19 的兼容声明不包含 rc.3。

插件不要求用户单独运行模型网关或配置 API key。宿主提供 Cordis、LLM、授权、凭据、Remote 和客户端服务。

## 推荐：安装 Release 预构建包

1. 打开本仓库 [Releases](https://github.com/isjya/dsh-chatgpt-pass/releases)，选择版本。
2. 下载 `dsh-chatgpt-pass-<版本>.tgz` 和同名 `.sha256` 文件。
3. 在 Harness 的 **插件 → 添加插件** 中选择本地 `.tgz`，完成安装后启用或重启。
4. 确认 **设置 → ChatGPT 订阅** 页面已出现。

Windows 可核对 SHA256，结果应与下载的校验文件一致：

```powershell
Get-FileHash -Algorithm SHA256 ./dsh-chatgpt-pass-<版本>.tgz
```

CLI 安装方式：

```sh
dsh plugin --profile <profile> add ./dsh-chatgpt-pass-<版本>.tgz
```

安装包已包含 `lib/`、bundle patch 和必要文档，没有安装时执行的生命周期脚本。不要把 GitHub 自动生成的 **Source code.zip / tar.gz** 当作插件安装包。

插件管理器支持下载链接时，可以直接粘贴 Release 中的 `.tgz` 地址；安装源保留默认 npm 官方源即可，不要将 GitHub 地址填入「自定义 npm 源」。本项目尚未发布到 npm，不能只输入包名来安装。

## 登录

打开 **设置 → ChatGPT 订阅**：

- **ChatGPT 登录**：使用官方 SIWC 授权，用量在 ChatGPT 页面查看。
- **订阅登录（含余量）**：Plus / Pro / Business / Team 均可使用，使用实验性 Codex 兼容连接查询余量（原「Business 登录」入口）。

只在 `auth.openai.com` 官方网页输入登录信息并授权。弹窗被拦截时使用设置页中的「继续授权」。登录可取消，超时后可重试。不要分享授权链接、回调、密码或令牌。

仅确认身份但未开启共享时，点击「启用订阅共享」。成功后在聊天模型选择器中选择实际模型。模型目录不代表真实推理资格已验证。

订阅余量连接借用 Codex 第一方 OAuth 客户端及 backend-api，并非 OpenAI 文档支持的第三方接入方式。它可能受工作区策略、条款和接口变更影响，不保证长期可用。

Plus / Pro 已连接官方路径时，点击用量区的「启用余量查询」。确认窗口会说明：这会替换当前连接、中止其在途请求，并要求重新授权；取消或按 Escape 不改变连接。完成授权后自动获取余量，切换后请新建会话。保留官方连接时可点击「在 ChatGPT 查看」，不会自动跨路径使用凭据。

## 用量与模型

订阅页显示脱敏账号和连接状态。「切换连接方式」用于重新登录，「可用模型」用于查看和刷新目录。Codex 用量以双行进度条显示剩余额度；悬停重置倒计时可查看完整时间。

在订阅页勾选「在侧边栏显示余量」，主窗口左侧栏底部、账号／设置入口上方会显示紧凑的 5 小时余量入口。点击可查看 5 小时与每周剩余比例、重置倒计时，并在弹出卡片内刷新；点击「订阅设置」会关闭弹窗，直接进入 Harness 内的「ChatGPT 订阅」设置页。点击外部或按 Escape 关闭。默认关闭，选择保存在插件配置中，重启仍保留。入口可见时约每分钟更新；收起侧边栏会隐藏入口，关闭该选项即可移除。

账号仅返回每周窗口时（例如部分 Pro 连接），侧边栏会显示每周余量；以接口返回的窗口为准，不补造 5 小时限额。

无数据时显示空状态，更新失败保留最近数据及其时间。数据以 ChatGPT 页面为准。当前没有已验证可用的账号级历史 Token 接口，因此未提供 7 / 30 天分析。刷新目录和用量不发送推理请求。

## 会话中切换模型

同一登录身份下，可以在现有会话中切换 ChatGPT 模型。插件保留历史正文和工具调用／结果，仅在本轮请求中移除旧模型的原生推理状态；不需要复制或清空原会话。切回原模型时，其有效原生状态仍可使用。

如果提示「当前登录身份与会话历史不一致」，请切回原连接身份，或新建会话并用文字补充必要上下文。如果提示「会话回放数据无效或版本不受支持」，表示历史校验仍未通过，原会话会保留；单纯切换模型不会再触发此错误。

## 运行失败与超时

旧版「响应协议不受支持或不完整，请检查插件版本」是一条通用提示，不能仅据此认定插件过旧。当前错误会区分上游限流／网关错误、上下文过长、响应校验失败和超时。`PROTOCOL` 的固定诊断原因会指出文本、工具、推理或结束事件等失败类别；可提供错误码和诊断原因排查，无需分享完整会话或授权信息。

默认等待响应头与等待后续事件的时限均为 120 秒。较早版本等待响应头仅 30 秒。需要调整时，可在该插件的 Harness 配置 `config` 中设置 `responseTimeoutMs` 和 `idleTimeoutMs`（毫秒，1000–600000 的整数）。

插件会在尚未输出任何文字、推理或工具调用时，对明确的网络故障、超时和临时服务错误自动重试，默认最多两次，约等待 1 秒、2 秒并加入随机变化。临时限流按有效的 `Retry-After` 等待，超过上限则停止；额度耗尽和未能区分原因的 429 不自动重试。已有部分输出时保留失败记录，需手动继续。重试可能额外消耗订阅用量；不会重复执行之前已完成的工具。

恢复配置位于 `config.recovery`：`maxRetries` 默认 2（0–3，0 表示关闭）；`initialDelayMs` 默认 1000，`maxDelayMs` 默认 30000（均为 1–600000 的整数，初始值不得超过上限）；`jitterRatio` 默认 0.2（0–1）。新请求使用最新配置，正在进行的请求保持原设置。

遇到卡顿可在 **设置 → ChatGPT 订阅 → 重新连接** 重置本插件的请求状态。有在途请求时，会先弹窗显示数量并提醒可能影响其他聊天；取消或按 Escape 不中断任务，选择「中止请求并重连」才会停止全部在途请求及重试等待。没有在途请求时直接重连。登录、聊天历史和已完成工具结果会保留，重连后不会自动补发聊天任务，请按需手动继续。

出现 429 时等待额度或频率限制恢复；出现 502／503／504 时稍后重试；上下文过长时使用宿主的上下文压缩或新会话。对已完成工具操作的任务，先核对已有结果再决定如何继续。

## 升级与卸载

通过同一入口安装新版本 `.tgz` 并重启 Harness。支持的凭据记录会保留；未知 schemaVersion 会停止写入，避免覆盖数据。

### 从旧包名迁移

本仓库 v0.2.14 及更早版本使用 `dsh-chatgpt-provider`，自 v0.2.15 起改为 `dsh-chatgpt-pass`。由于包名改变，需要先在插件管理器中移除旧包，再添加新包并重启。迁移时不要在订阅页点击「退出登录」。CLI 示例：

```sh
dsh plugin --profile <profile> remove dsh-chatgpt-provider
dsh plugin --profile <profile> add ./dsh-chatgpt-pass-<版本>.tgz
```

provider ID、凭据键和账号身份保持不变，已保存的模型选择与登录记录可继续使用。不要同时启用新旧两个包。

### 卸载

卸载前可在订阅页点击「退出登录」，再从插件管理器移除，或执行：

```sh
dsh plugin --profile <profile> remove dsh-chatgpt-pass
```

本地退出不一定代表远端授权已撤销，可在 [ChatGPT 设置](https://chatgpt.com/settings/usage) 管理远端连接。插件不会删除 Harness 会话或其他 provider 数据。

## 开发者安装

先按 [开发指南](DEVELOPMENT.md) 安装依赖并构建，再通过 `dsh plugin --profile <profile> add /path/to/dsh-chatgpt-pass` 链接本地目录。修改后需要重新构建。

直接 Git 安装源码需要 `prepare` 和用户的构建授权。本项目未设置 `prepare`，以 Release 预构建 `.tgz` 为推荐分发方式，不应将 Git 仓库 URL 直接作为安装入口。
